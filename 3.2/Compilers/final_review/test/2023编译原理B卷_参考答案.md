## 一、判断题（10 小题，每题 1 分，共 10 分）

### 1. DFA 中不允许 ε 变迁，所以任何 DFA 均无法识别空串。

**✗ 错误。**

DFA **不需要** ε 变迁也能识别空串 ε：只要令**初始状态同时为接受状态**即可。当输入为空串时，DFA 不做任何转移、停在初始（接受）状态，即接受 ε。ε 变迁的有无与能否识别空串无关。

---

### 2. 任给一个 NFA，都可以构造一个与之等价的 DFA。

**✓ 正确。**

这是**子集构造法（subset construction）**的核心结论：NFA 与 DFA 识别的语言类相同（都是正规语言），任何 NFA 都可转化为等价的 DFA（状态数为原 NFA 状态子集，最坏 2ⁿ 个）。

---

### 3. 文法 `A → Ba | a`，`B → A` 不存在左递归。

**✗ 错误。**

存在**间接左递归**：
```
A → B a → A a
```
即 `A ⇒ A a`，是左递归。虽无直接左递归（`A → A…`），但经 `B` 一步间接形成 `A → A a`，属间接左递归。

---

### 4. CFG 中任一句子都可构造分析树，内部结点均为非终结符，叶结点均为终结符。

**✓ 正确。**

这是分析树（parse tree）的定义性质：根为开始符号（非终结符），内部结点都是非终结符，叶子都是终结符（句子只含终结符，故无 ε 叶子）。句子是仅由终结符组成的句型，其分析树叶子全部为终结符。

---

### 5. 任给一个 LL(0) 文法，它所产生的语言最多只能包含一个句子。

**✓ 正确。**

LL(0) 意味着**不向前看任何输入符号**就能确定产生式选择，故对每个非终结符最多只能有一个可选产生式（多个候选会因无法据输入区分而冲突）。从开始符号出发推导路径唯一确定 ⟹ 只能产生唯一一个句子。故语言最多含一个句子。

---

### 6. 合并 LR(1) 状态得到 LALR(1) 时，合并可能产生新的归约-归约冲突和移进-归约冲突。

**✗ 错误。**

合并**同心集**（LR(0) 核心相同、lookahead 不同）时：
- **不会**产生新的**移进-归约冲突**：移进动作只取决于 LR(0) 核心，合并后核心不变，移进集合不变；而规约的 lookahead 是原两状态 lookahead 的并集，但移进符号若原本不属于任一状态的规约 lookahead，则合并后仍不属于并集（并集元素必来自其中之一）。
- **可能**产生新的**归约-归约冲突**：两状态中不同规约项目各自的 lookahead 合并后可能相交 ⟹ 新冲突。

故"产生新的移进-归约冲突"是错的。

---

### 7. L-属性定义适合自顶向下递归下降预测分析实现，不能在自底向上 LR 分析中实现。

**✗ 错误。**

L-属性定义**既**可在自顶向下分析中实现，**也**可在自底向上分析中实现（龙书"自底向上计算继承属性"：通过删除嵌入动作、改造文法、利用分析栈传递继承属性）。"不能在自底向上实现"错误。

---

### 8. 语法制导翻译中，回填（Backpatching）可解决生成跳转指令时跳转目标尚未确定的问题。

**✓ 正确。**

回填正是为此设计：先生成跳转指令但目标暂留占位符（跳转表），待目标地址确定后再统一回填，避免多遍扫描。

---

### 9. 全局优化指的是跨多个子程序进行代码调整。

**✗ 错误。**

**全局优化（global optimization）**指**跨基本块**的优化（在整个控制流图/函数内基于数据流分析）。跨多个子程序（函数/过程）的优化称为**过程间优化（interprocedural optimization）**。二者概念不同。

---

### 10. 中间代码优化时需考虑指令选择、指令调度、寄存器分配与指派等问题。

**✗ 错误。**

指令选择、指令调度、寄存器分配与指派属于**目标代码生成（code generation）**阶段的问题，**不是中间代码优化阶段**的问题。中间代码优化关注基本块优化与全局数据流优化（常量传播、复写传播、死代码删除、公共子表达式消除、循环优化等）。

## 二、填空题（7 小题，10 空，每空 1 分，共 10 分）

### 1. 文法分类

文法：
```
S  → a A C  |  a S A C
a A → a b
b A → b b
b C → b c
c C → c c
```

判断依据：产生式左部出现 `aA`、`bA`、`bC`、`cC`（**长度 > 1 且含终结符**），故**不是 CFG（2 型）**。检查 1 型（上下文有关）的长度非递减条件 `|左| ≤ |右|`：

| 产生式 | \|左\| | \|右\| |
|--------|------|------|
| S→aAC | 1 | 3 ✓ |
| S→aSAC | 1 | 4 ✓ |
| aA→ab | 2 | 2 ✓ |
| bA→bb | 2 | 2 ✓ |
| bC→bc | 2 | 2 ✓ |
| cC→cc | 2 | 2 ✓ |

全部满足，且左部为"上下文+非终结符"形式 ⟹ **上下文有关文法（1 型文法）**。

**答案：上下文有关文法（1 型文法，CSG）**

---

### 2. 活前缀

最右推导 `S ⟹ aaAb ⟹ aacBb`，句型 `aacBb` 的句柄为 `cB`。

活前缀定义：规范句型中**从左端到句柄末尾的任意前缀**。句柄 `cB` 位于第 3、4 符号位（`a a [c B] b`），句柄末尾前缀即 `aacB` 的所有前缀：

**答案：`ε, a, aa, aac, aacB`**（即 `aacB` 的所有前缀）

---

### 3. LL(1) 条件

对任意两个不同产生式 `A → α | β`：

- **第一空**：`FIRST(α) ∩ FIRST(β) = ∅`
- **第二空**：若 `ε ∈ FIRST(α)`，则 `FIRST(β) ∩ FOLLOW(A) = ∅`（且要求 `ε ∉ FIRST(β)`）

---

### 4. SLR(1) 分析表列数（m 个非终结符，n 个终结符）

- **ACTION 表列数** = `n + 1`（n 个终结符 + 结束符 `$`）
- **GOTO 表列数** = `m`（m 个非终结符）

---

### 5. 属性含义（`S → if ( B ) S₁`）

- **`B.true`**：布尔表达式 `B` 为**真**时控制流转移到的目标标号（即 `then` 部分 `S₁` 代码的起始地址）。
- **`S.next`**：语句 `S` 执行**结束后**控制流转移到的目标标号（`S` 的后继语句地址 / 出口标号）。

---

### 6. 无法回收循环引用的垃圾回收算法

**答案：引用计数法（Reference Counting）**

引用计数仅靠引用个数判断，循环引用的对象相互引用导致计数均不为 0，无法被回收；需借助追踪式（tracing，如标记-清除）算法才能回收。

---

### 7. 指令序列开销

```
LD  R0, b
ADD R0, R0, c
ST  a, R0
```

龙书约定每条指令开销为 1，共 3 条 ⟹ **开销 = 3**。

## 三、简答题（4 小题，每题 5 分，共 20 分）

### 1. 文法 `E → E - E | F`，`F → id` 是否二义？

**有二义性。** `E → E - E` 未规定运算符 `-` 的结合性与优先级，含多个 `-` 的句子可构造多棵分析树。

**举例**：句子 `id - id - id` 有两棵不同分析树。

**最左推导 1（左结合 `(id-id)-id`）**：
```
E ⇒ E - E
  ⇒ E - E - E          (左 E → E-E)
  ⇒ F - E - E          (最左 E → F)
  ⇒ id - E - E
  ⇒ id - F - E
  ⇒ id - id - E
  ⇒ id - id - F
  ⇒ id - id - id
```

**最左推导 2（右结合 `id-(id-id)`）**：
```
E ⇒ E - E
  ⇒ F - E              (左 E → F)
  ⇒ id - E
  ⇒ id - E - E         (右 E → E-E)
  ⇒ id - F - E
  ⇒ id - id - E
  ⇒ id - id - F
  ⇒ id - id - id
```

两棵分析树（树形）：
```
左结合：      -              右结合：      -
            /   \                        /   \
           -    id                     id    -
          / \                               / \
         id id                            id id
```
对应同一句子 ⟹ 文法二义。□

### 2. 翻译模式

```
(1) D → T    { L.type = T.type }   L
(2) T → int  { T.type = int }
(3) T → float { T.type = float }
(4) L → { L₁.type = L.type }  L₁ , id  { addtype(id.entry, L.type) }
(5) L → id   { addtype(id.entry, L.type) }
```

#### 2.1 T.type 与 L.type 是综合还是继承？

- **`T.type`：综合属性**。在 (2)(3) 中由 T 的子节点 `int`/`float` 决定（`T.type = int/float`），自底向上求值。
- **`L.type`：继承属性**。在 (1) 中 `L.type = T.type`（从父节点 D 的子节点 T 处继承），在 (4) 中 `L₁.type = L.type`（从 L 继承给 L₁），属性沿树自顶向下传递。

#### 2.2 `int y, z;` 的带注释分析树

分析树结构（`D → T L`，`L → L₁ , id(z)`，`L₁ → id(y)`）：

```
              D
           /     \
         T         L                 ← L.type = int (继承自 T)
       (T.type=int)
         |       / | \
        int    L₁  ,  id(z)          ← L₁.type = int (继承自 L)
                |              addtype(z, int)
               id(y)
              addtype(y, int)
```

**属性求值过程**：
1. `T → int` ⟹ `T.type = int`；
2. `D → T L`，动作 `{ L.type = T.type }` ⟹ `L.type = int`（顶层 L）；
3. `L → L₁ , id(z)`，动作 `{ L₁.type = L.type }` ⟹ `L₁.type = int`；后执行 `{ addtype(z.entry, int) }` ⟹ z 的类型登记为 int；
4. `L₁ → id(y)`，动作 `{ addtype(y.entry, L₁.type) }` ⟹ `{ addtype(y, int) }` ⟹ y 的类型登记为 int。

**结果**：`y` 和 `z` 均被登记为 `int` 类型。□

### 3. 划分基本块并画流图

中间代码：
```
1:   load A
2:   load B
3: L0: C := A mul B
4:   if C > 56 goto L1
5:   A := A + 1
6:   B := B + 1
7:   goto L0
8: L1: store C
9:   halt
```

**首语句判定**：① 第 1 条（程序开始）；② 跳转目标 `L0`（第 3 条）、`L1`（第 8 条）；③ 跳转语句后第 4 条后是第 5 条、第 7 条后是第 8 条。

⟹ 首语句：**1, 3, 5, 8**

| 基本块 | 语句 |
|--------|------|
| B1 | 1, 2 |
| B2 | 3, 4 (L0) |
| B3 | 5, 6, 7 |
| B4 | 8, 9 (L1) |

**流图**：
```
   B1 ──顺序──> B2
                 │
        ┌────────┴────────┐
   if真(goto L1)      if假(顺序)
        │                │
        ▼                ▼
        B4              B3
        │                │
       halt        goto L0
                       │
        ┌──────────────┘
        ▼
        B2   (回边，构成循环 B2→B3→B2)
```

**有向边**：
- `B1 → B2`（顺序）；
- `B2 → B3`（`if C>56` 为假，顺序执行）；
- `B2 → B4`（`if C>56` 为真，`goto L1`）；
- `B3 → B2`（`goto L0`，回边，构成循环）；
- `B4` 后 `halt` 结束。

### 4. 基本块优化

基本块：
```
1: S1 := 10
2: S2 := 40 / S1
3: S3 := X - Y
4: S4 := X + Y
5: A  := S2 * S4
6: B  := A
7: S5 := X + Y
8: S6 := S3 * S5
9: B  := S6
```
出口活跃：`A, B`。

**DAG 分析与优化**：

1. **常量折叠**：`S1 := 10` ⟹ `S2 := 40 / 10 = 4`（编译期算出，`S1`、`S2` 均可消除，`4` 直接内联）。
2. **公共子表达式消除**：`S5 := X + Y` 与 `S4 := X + Y` 相同 ⟹ 删除 `S5`，后续 `S6 := S3 * S5` 改为 `S6 := S3 * S4`。
3. **复写传播 + 死代码删除**：
   - `B := A`（第 6 条）后 `B` 在第 9 条被重新定值，且中间未使用 `B` ⟹ 第 6 条 `B := A` 是死代码，删除；
   - `S6 := S3 * S4` 后 `B := S6` ⟹ 合并为 `B := S3 * S4`，`S6` 消除。
4. **活跃性裁剪**：`S1, S2, S5, S6` 非出口活跃且已被消除；`S3, S4` 虽非出口活跃，但被活跃变量 `A, B` 使用，**必须保留**。

**最终优化后的基本块**（9 条 → 4 条）：
```
S4 := X + Y      ; 合并 S4 与 S5（公共子表达式）
S3 := X - Y
A  := 4 * S4     ; S2 常量折叠为 4 并内联
B  := S3 * S4    ; S5=S4 复写传播，B:=A 死代码删除
```

> 验证：`A = 4·(X+Y)`，`B = (X−Y)·(X+Y)`，与原语义一致（`A = (40/10)·(X+Y) = 4(X+Y)`；`B = (X−Y)·(X+Y)`）。□

## 四、应用题（3 小题，共 60 分）

### 1.（15 分）语言 L：Σ = {a, b}，每句中 a 的个数是 3 的倍数（含 0）

#### 1.1（8 分）正则表达式

思路：用 3 个状态记录"已读 a 的个数 mod 3"。从 mod 3 = 0 回到 mod 3 = 0，必须恰好经过 3 个 a，a 之间可夹任意个 b；开头可任意 b。

**正则表达式**：

$$
L = \mathbf{b^* (a\, b^*\, a\, b^*\, a\, b^*)^*}
$$

即 **`b*(ab*ab*ab*)*`**。

**解释**：
- 开头 `b*`：0 个 a 时只有任意 b；
- 每组 `a b* a b* a b*`：恰好 3 个 a，a 之间夹任意 b，使 a 计数 mod 3 从 0 → 1 → 2 → 0；
- 外层 `*`：可重复 0 次或多次，共 3k 个 a（k ≥ 0）。

**验证**：
- `ε`：`b*=ε`, `()*=ε` ✓（0 个 a）
- `aaa`：`b*=ε`, 一组 `a a a` ✓
- `baabab`：`b` + `a a` + `b` + `a` + `b` = 3 个 a ✓
- `aab`（2 个 a）：无法匹配，非 L ✓

#### 1.2（7 分）识别 L 的 DFA

三状态 DFA（记录 a 的个数 mod 3）：

| 状态 | 含义 | a | b | 接受？ |
|------|------|---|---|--------|
| q0 | mod 3 = 0 | q1 | q0 | ✓（开始+接受） |
| q1 | mod 3 = 1 | q2 | q1 | ✗ |
| q2 | mod 3 = 2 | q0 | q2 | ✗ |

```
        a            a            a
   ┌────────┐   ┌────────┐   ┌────────┐
   ▼        │   ▼        │   ▼        │
  (q0)─────►(q1)────────►(q2)─────────┘
   │ ▲  b     │  b        │  b
   │ └────────┘           │
   └─── b 自环 (q0)       (q1 b 自环, q2 b 自环)
   b*                    
```

**形式化**：`M = ({q0,q1,q2}, {a,b}, δ, q0, {q0})`
- `δ(q0,a)=q1, δ(q0,b)=q0`
- `δ(q1,a)=q2, δ(q1,b)=q1`
- `δ(q2,a)=q0, δ(q2,b)=q2`

该 DFA 最小（3 状态不可合并：q0 接受，q1/q2 不接受且转移不同）。□

### 2.（20 分）文法 G1 与 LL(1) 分析

```
S → A B a
A → A b | ε
B → d B | c
```

#### 2.1（2 分）句子 `bddca` 的分析树

- `A ⇒ A b ⇒ ε b = b`（用 `A→Ab`，内层 `A→ε`）；
- `B ⇒ d B ⇒ d d B ⇒ d d c`。

分析树：
```
            S
          / | \
         A  B  a
        /| /|\
       A b d B
       |    /|\
       ε    d B
             |
             c
```
叶子（左→右）：`b d d c a`（ε 忽略）= `bddca` ✓

#### 2.2（2 分）是否适合自顶向下？改写 G2

**不适合**。`A → A b` 是**左递归**，自顶向下（递归下降 / LL(1)）会无限递归，无法处理。

**消除左递归**（`A → A b | ε`，α=b，β=ε）：
```
A  → A'        (即 β A' = ε A')
A' → b A' | ε
```

**等价文法 G2**：
```
S  → A B a
A  → A'
A' → b A' | ε
B  → d B | c
```
（B 已是右递归，自顶向下可处理。）

#### 2.3（4 分）G2 的 FIRST / FOLLOW

**FIRST**：
- `FIRST(A') = {b, ε}`
- `FIRST(A) = FIRST(A') = {b, ε}`
- `FIRST(B) = {d, c}`
- `FIRST(S) = FIRST(A B a)`：A 可空 ⟹ `(FIRST(A)\{ε}) ∪ FIRST(B) = {b} ∪ {d,c} = {b, d, c}`

**FOLLOW**：
- `FOLLOW(S) = {$}`
- `S → A B a`：A 后跟 B（B 不可空）⟹ `FOLLOW(A) ⊇ FIRST(B) = {d, c}`；B 后跟 a ⟹ `FOLLOW(B) ⊇ {a}`
- `A → A'`：`FOLLOW(A') ⊇ FOLLOW(A) = {d, c}`
- `A' → b A'`：自反无新信息
- `B → d B`：自反无新信息

| 非终结符 | FIRST | FOLLOW |
|----------|-------|--------|
| S | {b, d, c} | {$} |
| A | {b, ε} | {d, c} |
| A' | {b, ε} | {d, c} |
| B | {d, c} | {a} |

#### 2.4（6 分）LL(1) 分析表与判定

产生式编号：
```
(1) S  → A B a
(2) A  → A'
(3) A' → b A'
(4) A' → ε
(5) B  → d B
(6) B  → c
```

**SELECT 集**：
- (1) `S→ABa`：`FIRST(ABa)={b,d,c}`
- (2) `A→A'`：`FIRST(A')={b,ε}`，非 ε 部分 `{b}`；A' 可空 ⟹ 加 `FOLLOW(A)={d,c}` ⟹ `{b,d,c}`
- (3) `A'→bA'`：`{b}`
- (4) `A'→ε`：`FOLLOW(A')={d,c}`
- (5) `B→dB`：`{d}`
- (6) `B→c`：`{c}`

**LL(1) 分析表**：

|  | b | d | c | a | $ |
|---|---|---|---|---|---|
| **S** | (1) | (1) | (1) |  |  |
| **A** | (2) | (2) | (2) |  |  |
| **A'** | (3) | (4) | (4) |  |  |
| **B** |  | (5) | (6) |  |  |

#### 3.5（4 分）G2 状态 I₈ 的冲突与 SLR(1) 解析

G2 的 LR(0) DFA 中状态：
```
I8:
T → b ·
T → b · E
E → · ( E )
E → · a
```

**冲突分析**：
- `T → b ·`：**规约项目**（用 `T → b` 规约）；
- `T → b · E` + `E → ·(E)` + `E → ·a`：点号在 E 前，遇到 `(` 或 `a` 时需**移进**（goto 到 E 的状态）。

故当向前看符号为 `(` 或 `a` 时：既可规约（`T→b`）又可移进 ⟹ **移进-规约冲突**。

**SLR(1) 是否可解析？**

G2 中 `FOLLOW(T)`：由 `S → E + T`，T 在末尾 ⟹ `FOLLOW(T) ⊇ FOLLOW(S) = {$}`；T 仅此出现 ⟹ `FOLLOW(T) = {$}`。

- 规约 `T → b` 仅在 `FOLLOW(T) = {$}` 列进行；
- 移进符号为 `{ (, a }`；
- `{ $ } ∩ { (, a } = ∅` ⟹ 规约与移进的向前看符号不重叠。

**结论**：SLR(1) **可解析**此冲突（在 SLR(1) 分析表中，规约项 `T→b` 只填 `$` 列，移进项填 `(`、`a` 列，无多重定义）。

#### 3.6（4 分）LR(1) 如何改进 SLR(1)；G2 的 LR(1) DFA 初始状态

**LR(1) 对 SLR(1) 的改进**：
- SLR(1) 用**全局 FOLLOW 集**判断规约：只要向前看符号 ∈ `FOLLOW(A)` 就规约 `A→α`。FOLLOW 集对所有出现通用，可能过大，导致无法消解的冲突。
- LR(1) 为每个项目携带**特定向前看符号（lookahead）** `[A → α·, a]`，该 lookahead 由项目在状态中的**上下文传播**得到，通常比 FOLLOW 集更精确（更小），从而能消解 SLR(1) 无法消解的冲突。

**G2 的拓广文法**：
```
(0) S' → S
(1) S  → E + T
(2) E  → ( E )
(3) E  → a
(4) T  → b
(5) T  → b E
```

**LR(1) DFA 初始状态 I₀** = closure({[S' → ·S, $]})：

闭包规则：`[A → ·Bβ, a]` ⟹ 对 `B → γ`，加入 `[B → ·γ, b]`，`b ∈ FIRST(β a)`。

- `[S' → ·S, $]`（初始）
- 由 `S'→·S`（β=ε，S 后无符号）⟹ `S` 的产生式 lookahead = `FIRST(ε$) = {$}`：
  - `[S → ·E + T, $]`
- 由 `S → ·E + T`（β = `+T`）⟹ `E` 的产生式 lookahead = `FIRST(+T $) = {+}`：
  - `[E → ·( E ), +]`
  - `[E → ·a, +]`

**I₀**：
```
[ S' → ·S,     $ ]
[ S  → ·E + T, $ ]
[ E  → ·( E ), + ]
[ E  → ·a,     + ]
```

> **对比**：SLR(1) 中 `E` 的规约用 `FOLLOW(E) = {+, ), $}`；而 LR(1) 初始状态中 `E` 相关项目的 lookahead 仅 `{+}`（更精确），这正是 LR(1) 强于 SLR(1) 的体现——在初始上下文中 `)` 和 `$` 不会紧跟 `E`，故不需要它们作为 lookahead。□

| 应用 | a 个数 mod 3 的正则式与 DFA、消除左递归+FIRST/FOLLOW+LL(1) 表+分析过程、LR(0) DFA+SLR(1) 表+输入分析+冲突解析+LR(1) 初始状态 |

> **关键复习点**：
> 1. **LALR 合并只新增归约-归约冲突，不新增移进-归约冲突**（高频考点）。
> 2. **间接左递归**：`A→B…, B→A…` 形式仍属左递归，自顶向下不可处理。
> 3. **活前缀**=规范句型中从左端到句柄末尾的任意前缀。
> 4. **LL(1) 条件**：`FIRST(α)∩FIRST(β)=∅`；若 `ε∈FIRST(α)` 则 `FIRST(β)∩FOLLOW(A)=∅`。
> 5. **SLR(1) 冲突解析**：看 `FOLLOW(规约左部)` 是否与移进符号集相交。
> 6. **LR(1) vs SLR(1)**：LR(1) 用项目特定 lookahead，比全局 FOLLOW 精确。
> 7. **DAG 优化顺序**：常量折叠 → 公共子表达式消除 → 复写传播 → 死代码删除，最后按活跃性裁剪并重排。
