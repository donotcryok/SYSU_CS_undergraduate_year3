复习并行计算这三大神器（OpenMP、Pthreads、MPI）确实是个不小的工程！为了方便你记忆，我们可以从**核心思想**出发：**Pthreads** 是最底层的“手动挡”（共享内存），**OpenMP** 是基于编译器的“自动挡”（共享内存），而 **MPI** 则是跨越不同机器的“对讲机”（分布式内存）。

以下为你整理的常用 API 总结及多维度的对比复习指南：

---

### 一、 OpenMP (共享内存，基于编译器指令)

**记忆口诀**：加一行 `#pragma` 就能让 `for` 循环起飞的“魔法”。适合多核 CPU 上的数据并行。

#### 1. 核心编译指令 (Directives)

* `#pragma omp parallel`：开辟并行域，大括号内的代码由多个线程同时执行。
* `#pragma omp for`：将紧跟其后的 `for` 循环任务自动分配给多个线程（通常与 parallel 合用：`#pragma omp parallel for`）。
* `#pragma omp sections`：定义多个独立的代码块，交由不同线程分别执行。

#### 2. 同步控制 (Synchronization)

* `#pragma omp critical`：临界区，保证同一时间只有一个线程执行该代码块（防止数据竞争）。
* `#pragma omp atomic`：原子操作，比 critical 更轻量，专门用于对单个内存位置的更新（如 `x++`）。
* `#pragma omp barrier`：隐式或显式屏障，所有线程运行到这里必须互相等待，齐了再往下走。

#### 3. 常用运行时函数 (Runtime API)

* `omp_get_thread_num()`：获取当前线程的 ID（主线程通常是 0）。
* `omp_get_num_threads()`：获取当前并行域中的总线程数。
* `omp_set_num_threads(int)`：手动设置接下来并行域要使用的线程数。

---

### 二、 Pthreads (POSIX Threads - 共享内存，底层 API)

**记忆口诀**：纯手动管理生命周期，高度定制化，适合需要复杂控制流的任务并行。

#### 1. 线程管理 (Thread Management)

* `pthread_create(...)`：生孩子。创建一个新线程并执行指定的回调函数。
* `pthread_join(...)`：等孩子。阻塞调用线程，直到指定的线程执行结束（并回收资源）。
* `pthread_exit(...)`：自杀。线程主动结束自己，可以返回一个状态指针。

#### 2. 互斥锁 (Mutexes - 防止数据竞争)

* `pthread_mutex_init(...)` / `pthread_mutex_destroy(...)`：初始化 / 销毁锁。
* `pthread_mutex_lock(...)`：加锁（如果别人锁了，我就阻塞等）。
* `pthread_mutex_unlock(...)`：解锁。

#### 3. 条件变量 (Condition Variables - 线程间通信/等待)

* `pthread_cond_wait(...)`：释放锁并陷入沉睡，直到被其他线程唤醒。
* `pthread_cond_signal(...)`：叫醒一个正在等待该条件的线程。
* `pthread_cond_broadcast(...)`：广播，叫醒所有等待该条件的线程。

---

### 三、 MPI (Message Passing Interface - 分布式内存)

**记忆口诀**：每个进程都有自己独立的“房间”（内存），想交换数据只能靠“发快递”（消息传递）。适合跨节点的超算集群。

#### 1. 环境与进程信息 (Environment)

* `MPI_Init(...)` / `MPI_Finalize()`：所有 MPI 程序的“开机”和“关机”操作，必须成对出现。
* `MPI_Comm_rank(...)`：问“我是谁？”（获取当前进程的 ID，即 Rank）。
* `MPI_Comm_size(...)`：问“我们一共多少人？”（获取通信域中的总进程数）。

#### 2. 点对点通信 (Point-to-Point)

* `MPI_Send(...)`：阻塞发送。信不送达不回头。
* `MPI_Recv(...)`：阻塞接收。信等不到往下走。
* `MPI_Isend(...)` / `MPI_Irecv(...)`：非阻塞发送/接收（带 `I` 的就是 Immediate）。发完/提交申请后立刻去干别的事，之后用 `MPI_Wait()` 检查完成情况。

#### 3. 集合通信 (Collective - 一对多，多对一，多对多)

* `MPI_Bcast(...)`：广播。头目（Root）把同一份数据抄送给所有人。
* `MPI_Scatter(...)`：散播。头目把一个大数组切碎，一人分发一块。
* `MPI_Gather(...)`：收集。所有人把各自的一块数据上交给头目拼起来。
* `MPI_Reduce(...)`：归约。所有人交出数据，并且沿途进行数学计算（如求和 `MPI_SUM`、找最大值 `MPI_MAX`），结果存在头目那里。

### 四、 三大神器横向对比总结表 (速记版)

| 比较维度           | OpenMP                           | Pthreads                            | MPI                               |
| ------------------ | -------------------------------- | ----------------------------------- | --------------------------------- |
| **编程模型** | **共享内存** (多线程)      | **共享内存** (多线程)         | **分布式内存** (多进程)     |
| **操作单元** | 线程 (Thread)                    | 线程 (Thread)                       | 进程 (Process)                    |
| **抽象层级** | 高 (基于编译器指令)              | 低 (底层 C 库)                      | 中/高 (基于消息队列库)            |
| **上手难度** | ⭐极易 (加几行指令即可)          | ⭐⭐⭐较难 (全手动档)               | ⭐⭐⭐⭐难 (需考虑死锁和网络拓扑) |
| **并行粒度** | 细粒度为主 (循环层级)            | 粗/细皆可 (任务层级)                | 粗粒度为主 (进程级别)             |
| **数据通信** | 直接读写同一块内存               | 直接读写同一块内存                  | 显式调用收发函数 (Send/Recv)      |
| **同步机制** | 隐含或显式的 barrier / critical  | Mutex / 条件变量 (全手动)           | 消息本身的阻塞 /`MPI_Barrier`   |
| **适用场景** | 单机多核 CPU (比如加速 for 循环) | 复杂的单机多线程服务端/操作系统开发 | 跨物理机的超级计算机、集群计算    |

* **Pthreads** 是你在指挥一个车间里的多个工人（线程），你要亲自给每个工人分配工位，还得给危险工具上锁（Mutex）。
* **OpenMP** 是你拥有一个智能主管（编译器），你只要在流水线前喊一句“这段活你们分头干”（`#pragma omp parallel for`），主管就自动帮你把活儿分给工人了。

### **一、 判断题分析**

**题目：** L属性定义节点的继承属性来自左兄弟节点和父节点的继承属性和综合属性。

* **答案：** **正确 (T)**
* **解析：** 在L属性定义（L-Attributed Definition）中，一个节点的继承属性只能依赖于其父节点的继承属性，以及其在产生式右部**左侧**兄弟节点的任何属性（无论是继承还是综合）。

**题目：** 正规表达式和上下文无关文法能表示的语言一样。

* **答案：** **错误 (F)**
* **解析：** 正规表达式只能表示正则语言（Regular Languages，对应乔姆斯基3型文法），而上下文无关文法（CFG）能表示上下文无关语言（对应2型文法）。上下文无关语言的集合严格大于正则语言集合。

**题目：** 句柄是最右直接短语。

* **答案：** **错误 (F)**
* **解析：** 句柄（Handle）是指一个规范句型（由最右推导产生的句型）的**最左直接短语**，它标志着在自底向上分析中下一步应该被规约的子串。

**题目：** 符号表, AST, 三地址码都是编译器构造中产生的中间语言。

* **答案：** **错误 (F)**
* **解析：** 抽象语法树（AST）和三地址码是中间表示（IR/中间语言），但**符号表（Symbol Table）是一种数据结构**，用于记录变量、函数等标识符的属性，它贯穿编译器的各个阶段，本身不是一种中间语言。

**题目：** $E \rightarrow ee \mid Ee$ , $e$ 是该文法产生的句子。

* **答案：** **错误 (F)**
* **解析：** 从非终结符 $E$ 出发，最短的推导是直接使用 $E \rightarrow ee$，因此该文法能产生的最短句子是 $ee$。终结符 $e$ 单独无法被推导出来。

**题目：** 二义性语言只能由二义性文法产生。

* **答案：** **正确 (T)**
* **解析：** 这是先天二义性语言（Inherently Ambiguous Language）的定义。如果一个语言没有任何一个无二义性的上下文无关文法能够产生它，那么这个语言就是二义性语言。

**题目：** yacc 用最右推导比较多，yacc适合左递归还是右递归。

* **答案：** **适合左递归**
* **解析：** yacc/bison 使用的是 LALR(1) 分析法，属于自底向上分析（规约句柄）。自底向上分析处理**左递归**更为高效，因为左递归在栈中不会累积未规约的符号，而右递归会导致栈深度的不断增加，直到读到输入串末尾才能开始规约。

**题目：** LALR1 文法识别的语言的可以由 SLR1 识别。

* **答案：** **错误 (F)**
* **解析：** LALR(1) 的分析能力强于 SLR(1)。所有的 SLR(1) 文法都是 LALR(1) 文法，但反之不成立（有些 LALR(1) 文法无法用 SLR(1) 识别，因为 SLR(1) 使用的是全局的 Follow 集，容易产生规约-规约冲突）。

### **二、 填空题**

**消除左递归：** $Q \rightarrow Qc \mid d \mid \epsilon$

* **解答：**
  $Q \rightarrow dQ' \mid Q'$  （注：因为 $\epsilon \cdot Q' = Q'$）
  $Q' \rightarrow cQ' \mid \epsilon$

**移入-规约冲突：** 给定 $A \rightarrow Ad$ 和 $A \rightarrow d$，问其中有什么冲突？如果 $Ad\cdot$ 优先级更高，则此时应做什么动作。

* **解答：** **规约 (Reduce)**
* **解析：** 此时面临是把 $d$ 移入栈中还是把栈顶的 $Ad$ 规约为 $A$ 的冲突。如果规定 $Ad\cdot$ 项目（即规约项目）优先级更高，则应该执行规约动作。

**S属性定义：** S属性通常用（自顶向下/自底向上）的分析技术。

* **解答：** **自底向上 (Bottom-up)**
* **解析：** S属性定义只包含综合属性。在自底向上的 LR 分析中，规约时子节点的属性已经计算完毕，刚好可以在此时计算父节点的综合属性。

**二维数组三地址码：** 数组 `[10][20]`，大小为4，列数20。
设引用为 `A[i][j]`，按行优先存储。

* **解答：**

$t_1 = i * 20$  $t_2 = t_1 + j$  $t_3 = t_2 * 4$  $t_4 = base + t_3$

### **三、 简答题**

1. 二义性分析

**已知文法：**

$S \rightarrow SAS \mid a \mid b \mid (S)$ $A \rightarrow + \mid -$

**(1) 判断是否有二义性：** 有二义性 。

**(2) 举例二义性的句子：** $a+b+a$ 。

**(3) 给出两个最左推导并画出语法树：**

**最左推导 1（左结合优先级）：**
$S \Rightarrow SAS \Rightarrow aAS \Rightarrow a+S \Rightarrow a+SAS \Rightarrow a+bAS \Rightarrow a+b+S \Rightarrow a+b+a$
**最左推导 2（右结合优先级）：**
$S \Rightarrow SAS \Rightarrow SASAS \Rightarrow aASAS \Rightarrow a+SAS \Rightarrow a+bAS \Rightarrow a+b+S \Rightarrow a+b+a$
*(语法树略：推导1的树根节点S先分裂为左侧的 $a+b$ 和右侧的 $a$；推导2的树根节点S先分裂为左侧的 $a$ 和右侧的 $b+a$。)*

2. 划分基本块与构造流图

**代码片段：**
(1) `xx = 1`
(2) `xx = 2`
(3) `if xx goto L1`
(4) `XX`
(5) `XX`
(6) `goto L2`
(7) `L1: XX`
(8) `XX`
(9) `L2: halt`

**基本块划分：**

* **入口语句（Leaders）：** 第一句(1)、转移指令的目标(7)、转移指令的目标(9)、条件转移指令的下一句(4)。
* **基本块 (Blocks)：**
* **B1:** (1), (2), (3)
* **B2:** (4), (5), (6)
* **B3:** (7), (8)
* **B4:** (9)
* 

**控制流图 (CFG)：**

* B1 $\rightarrow$ B3 (条件为真，跳转到L1)
* B1 $\rightarrow$ B2 (条件为假，顺序执行)
* B2 $\rightarrow$ B4 (无条件跳转到L2)
* B3 $\rightarrow$ B4 (顺序执行到达L2)

3. 有向无环图 (DAG) 优化

**代码：**
(1) $A := 5$
(2) $B := 4 * A$
(3) $C := C + A$  (设初始为 $C_0$)
(4) $D := C + A$
(5) $E := C$
(6) $F := D + B$
*已知 D 和 F 在出口活跃* 。

**DAG 构造：**

* 节点 $n_1$: 值为 5，附加变量 $A$
* 节点 $n_2$: 值为 4
* 节点 $n_3$: 运算 `*` (左 $n_2$，右 $n_1$)，附加变量 $B$
* 节点 $n_4$: 初始值 $C_0$
* 节点 $n_5$: 运算 `+` (左 $n_4$，右 $n_1$)，附加变量 $C, E$
* 节点 $n_6$: 运算 `+` (左 $n_5$，右 $n_1$)，附加变量 $D$
* 节点 $n_7$: 运算 `+` (左 $n_6$，右 $n_3$)，附加变量 $F$
* 

**三种优化方案举例：**

1. **常数折叠 (Constant Folding)：** 编译期可直接计算 $A=5$，$B = 4 * 5 = 20$。
2. **复写传播与消除 (Copy Propagation)：** $E := C$ 是多余的，由于 $E$ 在出口不活跃，可以直接删除。
3. **死代码消除 (Dead Code Elimination)：** 因为出口处只有 $D$ 和 $F$ 活跃，中间变量 $A, B, C, E$ 的最终赋值如果后续不再使用，可以从目标代码的最终写回中删除。

### **四、 应用题**

1. 正则表达式 NFA 与 DFA

**表达式：** `(bala)*b*`

**(1) 中文描述：** 该语言由零个或多个连续的 "bala" 字符串，后跟零个或多个连续的字符 'b' 组成。

**(2) e-NFA 和 (3) 最小化 DFA**
*(步骤描述)*：可以通过 Thompson 算法构造 NFA，然后使用子集构造法将其转化为 DFA。最终的最小化 DFA 会包含一个识别 `bala` 循环的核心主干，并在任何接受状态允许接收任意数量的 `b` 停留在终态。

2. 消除左递归，构造 LL1 分析表

**文法：**

$S \rightarrow Qc$ $Q \rightarrow Qa \mid b \mid \epsilon$  （回忆版中的 `e` 代表 $\epsilon$）

* **消除左递归：**
  $S \rightarrow Qc$
  $Q \rightarrow bQ' \mid Q'$
  $Q' \rightarrow aQ' \mid \epsilon$
* **求 FIRST 和 FOLLOW 集：**
* $FIRST(Q') = \{a, \epsilon\}$, $FOLLOW(Q') = \{c\}$
* $FIRST(Q) = \{b, \epsilon\}$, $FOLLOW(Q) = \{c\}$
* $FIRST(S) = \{b, c\}$, $FOLLOW(S) = \{\$\}$
* **LL(1) 分析表：**

| 非终结符     | $a$                  | $b$                 | $c$                       | $\$$ |
| ------------ | ---------------------- | --------------------- | --------------------------- | ------ |
| **S**  |                        | $S \rightarrow Qc$  | $S \rightarrow Qc$        |        |
| **Q**  |                        | $Q \rightarrow bQ'$ | $Q \rightarrow Q'$        |        |
| **Q'** | $Q' \rightarrow aQ'$ |                       | $Q' \rightarrow \epsilon$ |        |

3. 中缀表达式转前缀 (语法制导翻译)

**任务：** 将中缀表达式转换成前缀表达式（操作符在前），存储在 `code` 综合属性中。
转换目标：`a*-(b+c)`

**语法制导翻译模式：**

1. $E \rightarrow E_1 + T \quad \{ E.code = \text{concat}('+', E_1.code, T.code) \}$
2. $E \rightarrow E_1 - T \quad \{ E.code = \text{concat}('-', E_1.code, T.code) \}$
3. $E \rightarrow T \quad \{ E.code = T.code \}$
4. $T \rightarrow T_1 * F \quad \{ T.code = \text{concat}('*', T_1.code, F.code) \}$
5. $T \rightarrow F \quad \{ T.code = F.code \}$
6. $F \rightarrow - F_1 \quad \{ F.code = \text{concat}('-', F_1.code) \}$ （处理一元负号）
7. $F \rightarrow (E) \quad \{ F.code = E.code \}$
8. $F \rightarrow \mathbf{id} \quad \{ F.code = \mathbf{id}.value \}$

### **五、 综合应用题**

补充 LR(1) 分析表项目

**文法：**

$S \rightarrow ADc$ $A \rightarrow ab \mid Ad$ $D \rightarrow Dc \mid d$

* 1. 扩充文法：
     引入新的开始符号 $S'$。
     (0) $S' \rightarrow S$
     (1) $S \rightarrow ADc$
     (2) $A \rightarrow ab$
     (3) $A \rightarrow Ad$
     (4) $D \rightarrow Dc$
     (5) $D \rightarrow d$
* 

**核心解析点：** 注意到文法中 $A \rightarrow Ad$ 和 $D \rightarrow Dc$ 都是**左递归**。在构造 LR(1) 项目集族时，闭包（Closure）的计算需要带上向前看符号（Lookahead）。例如，初始项目集 $I_0$ 的闭包会包含 $A \rightarrow \cdot ab, d$ 和 $A \rightarrow \cdot Ad, d$ （因为 $S \rightarrow \cdot ADc$，A后面的FIRST集包含了D的FIRST集，即 $\{d\}$）。

**栈状态追踪：** 题目提到分析 `abd$` 时栈里出现状态2终止 。这需要完整的项目集族 DFA 才能准确定位状态 2 的具体项目。通常状态 2 是移入了第一个终结符（比如 $a$）后的状态，如果在该状态遇到无法预期的转移，则分析终止报错。
