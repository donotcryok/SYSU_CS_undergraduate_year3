## 一、判断题（10 题）

### 1. L 属性定义：节点的继承属性来自左兄弟节点和父节点的继承属性和综合属性。

**✗ 错误。**

L 属性定义（L-attributed definition）的严格定义：对每个产生式 `A → X₁X₂…Xₙ`，符号 `Xᵢ` 的**继承属性**只能依赖于：

- `A` 的**继承属性**（注意：不是综合属性）；
- `Xᵢ` **左边**兄弟节点 `X₁…Xᵢ₋₁` 的任意属性（综合或继承）；
- `Xᵢ` 自身的相关属性（部分定义允许）。

题目说"父节点的**继承属性和综合属性**"是错误的——继承属性**不允许**依赖父节点的综合属性，否则可能产生循环依赖。正确说法是"父节点的继承属性"。

---

### 2. 正规表达式和上下文无关文法能表示的语言一样。

**✗ 错误。**

- 正规表达式 ⟺ 3 型文法（正规文法），产生**正规语言**；
- 上下文无关文法（2 型）产生**上下文无关语言（CFL）**；
- Chomsky 文法层次：3 型 ⊊ 2 型 ⊊ 1 型 ⊊ 0 型。

正规语言是上下文无关语言的**真子集**（例如 `aⁿbⁿ` 可由 CFG 产生但不是正规语言）。故二者能表示的语言**不一样**。

---

### 3. 句柄是最右直接短语。

**✗ 错误。**

句柄（handle）的定义：句型的**最左直接短语**。在规范规约（最右推导的逆过程）中，每一步被规约的串就是当前句型的句柄，它是**最左**直接短语，而非"最右"。

---

### 4. 符号表、AST、三地址码都是编译器构造中产生的中间语言。

**✗ 错误。**

- **AST（抽象语法树）**、**三地址码**：属于中间表示/中间语言；
- **符号表**：是用于记录标识符（名字、类型、作用域、存储位置等）信息的**数据结构**，**不是中间语言**。

故该说法错误。

---

### 5. `E → ee | Ee`，e 是该文法产生的句子。

**✗ 错误。**（题目中 e 为终结符）

文法 `E → ee | Ee`：每个产生式右部至少含两个 e（`ee` 或 `Ee`，而 `E` 本身又至少产生两个 e）。

- `E ⇒ ee`，故 `ee` 是句子；
- `E ⇒ Ee ⇒ ee e = eee`，也是句子；
- 但**单个 `e` 无法被推导出**（无法只产生一个 e）。

所以 `e` 不是该文法的句子，最小句子是 `ee`。

---

### 6. 二义性语言只能由二义性文法产生。

**✓ 正确。**

这是**二义性语言（inherently ambiguous language）**的定义：若一个上下文无关语言**不存在**任何无二义文法，则称该语言为（固有）二义性语言。因此"二义性语言只能由二义性文法产生"正是其定义，正确。

> 注意区分：二义性**文法**产生的语言不一定是二义性**语言**（可能存在等价的无二义文法）。

---

### 7. yacc 用最右推导比较多，yacc 适合左递归还是右递归。

**✓ 正确**（yacc 适合左递归文法）。

- yacc 基于 **LALR(1)** 分析，属于**自底向上**分析，对应**最右推导的逆**（最左规约），所以说"用最右推导"是对的。
- LR 类分析（含 LALR）**适合左递归文法**：左递归文法在自底向上分析中栈深度浅、效率高；而 LL 类分析必须消除左递归、更适合右递归。故"yacc 适合左递归"正确。

---

### 8. LALR(1) 文法识别的语言可以由 SLR(1) 识别。

**✗ 错误。**

文法分析能力：`LR(0) ⊊ SLR(1) ⊊ LALR(1) ⊊ LR(1)`。

LALR(1) 的分析能力**强于** SLR(1)，存在**是 LALR(1) 但非 SLR(1)** 的文法（即存在 SLR(1) 无法消解但 LALR(1) 可消解的移入-规约/规约-规约冲突）。因此不能笼统地说"LALR(1) 文法都可由 SLR(1) 识别"。

---

### 9. 给定文法，判断两个 Follow 集正确与否。

**【回忆缺失】** 原题未给出具体文法与两个 Follow 集，无法判定。

**判断方法**：对每个非终结符 `A`，按以下规则计算 `FOLLOW(A)`：

1. `FOLLOW(开始符号)` 含 `$`；
2. 若 `A → αBβ`，则 `FOLLOW(B) ⊇ FIRST(β) \ {ε}`；
3. 若 `A → αB`（或 `A → αBβ` 且 `β ⇒* ε`），则 `FOLLOW(B) ⊇ FOLLOW(A)`。

依此对照题给两个 Follow 集即可判断正误。

## 二、填空题（5 题，10 空）

### 1. 消除左递归 `Q → Qc | d | ε`

**分析**：左递归项 `Qc`（α = c），非递归项 `d`、`ε`（β₁ = d，β₂ = ε）。

由公式 `A → Aα | β₁ | β₂` 改写为 `A → β₁A' | β₂A'`，`A' → αA' | ε`：

```
Q  → d Q' | Q'        (即 d Q' | ε Q'，ε Q' 等价于 Q')
Q' → c Q' | ε
```

> **易错点**：不能写成 `Q → d Q' | ε`！因为原语言 `L(Q) = {cⁿ | n≥0} ∪ {d cⁿ | n≥0}`。若写成 `Q → d Q' | ε`，会**丢失** `{c, cc, …}`（只能产生 `ε` 和 `d cⁿ`），错误。
> 必须写成 `Q → d Q' | Q'`，由 `Q' ⇒ cⁿ` 来产生 `{cⁿ}`。

**验证**：`Q' ⇒ ε, c, cc, …`；`Q ⇒ d Q' ⇒ d, dc, dcc, …`；`Q ⇒ Q' ⇒ ε, c, cc, …`，合并得 `{d cⁿ} ∪ {cⁿ}` ✓

---

### 2. `A → A·d` 与 `A → d·` 的冲突；若 `A → d·` 优先级更高，应做什么动作。

**冲突类型**：**移入-规约冲突**（shift-reduce conflict）。

- `A → A·d`：点号在 d 前，可**移入** d；
- `A → d·`：点号在末尾，可**规约**（用 `A → d` 规约）；
- 当向前看符号为 `d` 时，两者同时可行 → 冲突。

**优先级更高时的动作**：若 `A → d·`（规约项）优先级更高，则应执行**规约（reduce）**，即按 `A → d` 进行规约。

---

### 3. S 属性通常用（自顶向下 / 自底向上）的分析技术。

**答案：自底向上**。

S 属性定义：所有属性均为**综合属性**。综合属性在子节点全部计算后、节点规约时计算，因此适合**自底向上**分析（规约时沿树自下而上求值）。

---

### 4. 二维数组 `A[10][20]` 转三地址码（元素大小 4，列数 20），补两个空。

数组 `A[i][j]`（行优先存储）的地址公式：

```
addr = base + (i × 20 + j) × 4
```

题目模板：

```
t1 = (        )
t2 = (        )
t3 = t2 * 4
t4 = base + t3
```

**填空**：

```
t1 = i * 20        ; 行偏移（每行 20 个元素）
t2 = t1 + j        ; 加上列偏移，得线性下标 i*20+j
t3 = t2 * 4        ; 乘以元素大小 4
t4 = base + t3     ; 基地址 + 字节偏移
```

即 **`t1 = i * 20`**，**`t2 = t1 + j`**。

### 5. 活跃变量分析填空。

**【回忆缺失】** 原题给出代码块与活跃变量表，挖两个空（一个写活跃变量，一个写产生式右边），具体式子已忘记，仅记得大致形式 `{x} 定义 a {} b=() {} 重新定义 a {a,b}`。

**解题方法**（供套用）：活跃变量数据流方程

- `OUT[B] = ∪ IN[S]`（B 的所有后继 S 的 IN 的并集）；
- `IN[B] = USE[B] ∪ (OUT[B] − DEF[B])`。

其中 `USE[B]` = 块 B 中**使用前未被定值**的变量集；`DEF[B]` = 块 B 中**定值前未被使用**的变量集。按**逆后序**迭代直至不变，即可填出各点的活跃变量集与对应产生式。

## 三、简答题（3 题）

### 1. 二义性分析

文法：

```
S → S A S | a | b | (S)
A → + | -
```

#### (1) 判断该文法是否有二义性

**有二义性。** 该文法允许 `S → S A S` 形式的递归嵌套，运算符 `+`/`-` 之间**未规定结合性与优先级**，对含多个运算符的句子可构造多棵不同的语法树，故文法二义。

#### (2) 举例二义性的句子

取句子 **`a + a + a`**（即 `a+a+a`）。它有两棵不同的语法树（分别对应左结合与右结合）。

#### (3) 给出两个最左（或最右）推导，并画语法树

**最左推导 1（左结合：`(a+a)+a`）**：

```
S ⇒ S A S
  ⇒ S A S A S          (左 S → S A S)
  ⇒ a A S A S          (最左 S → a)
  ⇒ a + S A S          (A → +)
  ⇒ a + a A S          (S → a)
  ⇒ a + a + S          (A → +)
  ⇒ a + a + a          (S → a)
```

**最左推导 2（右结合：`a+(a+a)`）**：

```
S ⇒ S A S
  ⇒ a A S              (左 S → a)
  ⇒ a + S              (A → +)
  ⇒ a + S A S          (S → S A S)
  ⇒ a + a A S          (左 S → a)
  ⇒ a + a + S          (A → +)
  ⇒ a + a + a          (S → a)
```

**语法树（树形示意）**：

推导 1（左结合）：

```
        S
       /|\
      S A S
     /|\   \
    S A S   a
    a + a   +
            (左子为 (a+a)，根 +，右子 a)
```

```
         +
        / \
       +   a
      / \
     a   a
```

推导 2（右结合）：

```
         +
        / \
       a   +
          / \
         a   a
```

两棵语法树对应同一句子 `a+a+a`，故文法二义。□

### 3. DAG

代码：

```
A := 5
B := 4 * A
C := C + A
D := C + A
E := C
F := D + B
```

出口活跃变量：`D`、`F`。

#### (1) 画 DAG

| 节点 | 操作                  | 子节点 | 附加标识符 |
| ---- | --------------------- | ------ | ---------- |
| n1   | 5（叶子常量）         | —     | A          |
| n2   | `*`                 | 4, n1  | B          |
| n3   | C₀（叶子，C 的初值） | —     | —         |
| n4   | `+`                 | n3, n1 | C, E       |
| n5   | `+`                 | n4, n1 | D          |
| n6   | `+`                 | n5, n2 | F          |

DAG 示意：

```
n3(C0)   4      n1(5)              n5(+)── D, 活跃
   \      \     /  \                /  \
    \      \  /     \              /    \
     n4(+)──C,E     \            /      n2(*)── B
        \            \          /        /  \
         \            \        /        4   n1(5)=A
          n5(+)── D    n1(5)── A
            \
             n6(+)── F, 活跃
```

> 说明：`E := C` 是复写，E 直接附加到 C 所在节点 n4。`A:=5` 后，`4*A`、`C+A`、`D:=C+A` 中 A 全部指向 n1（值 5）。

#### (2) 该 DAG 举例三种优化方案

**① 常量折叠 / 常量传播**

- `A := 5`，故 `B := 4 * A = 4 * 5 = 20`，可在编译期算出 `B := 20`。
- 同时 `C := C + 5`、`D := C + 5`（用 5 替换 A）。

**② 删除死代码**

- `E := C`：E **不在**出口活跃集 `{D, F}` 中，且 E 未被后续使用 → `E := C` 可删除（去掉标识符 E，节点 n4 仅保留 C）。

**③ 复写传播**

- `E := C` 是复写，删除后无影响；
- `B := 20`（常量）后，`F := D + B` 可传播为 `F := D + 20`，把 B 的值直接代入使用点，便于后续删除对 B 的定值。

**优化后的代码**（仅保留出口活跃的 D、F 相关计算）：

```
C := C + 5
D := C + 5
F := D + 20
```

（删除了 `A:=5`（已传播）、`B:=4*A`（折叠为 20 并内联）、`E:=C`（死代码）。）□

## 四、应用题（3 题）

### 1. 正则表达式 `(ba|a)*b*`

#### (1) 中文描述该正则表达式含义

该正则表达式表示的串由**两部分**拼接而成：

- **前半部分**：`(ba|a)*`，即由零个或多个 `ba` 或 `a` 连接而成——其中每个 `b` 之后**必须紧跟一个 `a`**，因此前半部分不会出现连续两个 `b`，也不以 `b` 结尾；
- **后半部分**：`b*`，即零个或多个 `b`。

整体含义：**一个由若干个 "ba" 或 "a" 组成的串，后面再接上若干个 "b"**。

#### (2) 画 ε-NFA（Thompson 构造）

构造等价 NFA（含 ε 转移）。设开始状态 0，接受状态 2：

```
            a
       ┌────────┐
       ▼        │
   ──>(0)────ε──>(2)  [接受]
       │  b        ▲
       ▼           │
       (1)──a──>(0)│
                   │
              (0)──ε──>(2)
              (2)──b──>(2)  [自环]
```

形式化（状态 0 为开始，2 为接受）：

- `0 --a--> 0`
- `0 --b--> 1`
- `1 --a--> 0`
- `0 --ε--> 2`（因为 `(ba|a)*` 可空，可直接进入 `b*` 部分）
- `2 --b--> 2`

> 上述为等价 NFA；若严格按 Thompson 算法从 `(ba|a)*b*` 逐层构造，会引入更多 ε 状态，但功能等价。

#### (3) 最小化 DFA

**① 子集构造（从上面 NFA 出发）**

`ε-closure({0}) = {0, 2}`（记为状态 A，含接受态 2，故接受）

| DFA 状态 | NFA 子集 | a 转移   | b 转移   | 接受？ |
| -------- | -------- | -------- | -------- | ------ |
| A        | {0,2}    | {0,2}→A | {1,2}→B | 是     |
| B        | {1,2}    | {0,2}→A | {2}→C   | 是     |
| C        | {2}      | ∅→D    | {2}→C   | 是     |
| D        | ∅（死） | ∅→D    | ∅→D    | 否     |

**未最小化 DFA**：

```
        a          b
A(起,接) ──> A ──> B(接)
B(接)     ──> A ──> C(接)
C(接)     ──> D ──> C
D         ──> D ──> D
```

**② Hopcroft 最小化**

初始划分：`{A,B,C}`（接受）、`{D}`（非接受）。

- 考察 `{A,B,C}`：
  - A：a→A(接受组)，b→B(接受组)
  - B：a→A(接受组)，b→C(接受组)
  - C：a→D(**非接受组**)，b→C(接受组)
  - C 与 A、B 不同（a 转移去向不同）→ 分裂为 `{A,B}`、`{C}`。
- 考察 `{A,B}`：
  - A：a→A，b→B（都去 `{A,B}` 组）
  - B：a→A，b→C（b 去 `{C}` 组）
  - A、B 不同 → 分裂为 `{A}`、`{B}`。

最终划分：`{A}`、`{B}`、`{C}`、`{D}`，已是最小。

**最小化 DFA（4 状态）**：

```
状态      a        b       说明
A(起,接)  A        B       已读 (ba|a)* 的前缀，可继续或转 b*
B(接)     A        C       刚读完一个 b（可能是 ba 的中间态）
C(接)     D(死)    C       已进入 b* 全 b 段
D(死)     D        D       一旦出现非法（如 b* 后再出 a）进入死态
```

**验证**：

- `ε`：A 接受 ✓（`(ba|a)*=ε, b*=ε`）
- `a`：A→A 接受 ✓
- `b`：A→B 接受 ✓（`b*=b`）
- `ba`：A→B→A 接受 ✓
- `bb`：A→B→C 接受 ✓（`b*=bb`）
- `bba`：A→B→C→D 拒绝 ✓（`b*` 后不能再有 a）
- `aba`：A→A→B→A 接受 ✓（`a` + `ba`）□

### 2. 消除左递归，构造 LL(1) 分析表

文法：

```
S → Q c
Q → Q a | b | ε
```

#### (1) 消除左递归

`Q → Q a | b | ε`，左递归项 `Qa`（α = a），非递归项 `b`、`ε`（β₁ = b，β₂ = ε）。

按公式 `A → Aα | β₁ | β₂` ⟹ `A → β₁A' | β₂A'`，`A' → αA' | ε`：

```
Q  → b Q' | Q'        (即 b Q' | ε Q'，等价于 b Q' | Q')
Q' → a Q' | ε
```

> **同填空题 1 的注意点**：不能写 `Q → b Q' | ε`，否则丢失 `{a, aa, …}`。原语言 `L(Q) = {b aⁿ} ∪ {aⁿ}`。
> 验证：`Q' ⇒ aⁿ`；`Q ⇒ b Q' ⇒ b aⁿ`；`Q ⇒ Q' ⇒ aⁿ` ✓

消除左递归后的完整文法：

```
(1) S  → Q c
(2) Q  → b Q'
(3) Q  → Q'
(4) Q' → a Q'
(5) Q' → ε
```

#### (2) 求 FIRST / FOLLOW

**FIRST**：

- `FIRST(Q') = {a, ε}`
- `FIRST(Q) = FIRST(bQ') ∪ FIRST(Q') = {b} ∪ {a, ε} = {a, b, ε}`
- `FIRST(S) = FIRST(Q c)`：Q 可空 ⟹ `FIRST(S) = (FIRST(Q)\{ε}) ∪ FIRST(c) = {a,b} ∪ {c} = {a, b, c}`

**FOLLOW**：

- `FOLLOW(S) = {$}`
- `S → Q c`：`FOLLOW(Q) ⊇ FIRST(c) = {c}`；Q 仅在此出现 ⟹ `FOLLOW(Q) = {c}`
- `Q → b Q'`：`FOLLOW(Q') ⊇ FOLLOW(Q) = {c}`
- `Q' → a Q'`：`FOLLOW(Q') ⊇ FOLLOW(Q')`（自反），`Q'` 后跟 `FOLLOW(Q')`
- ⟹ `FOLLOW(Q') = {c}`

#### (3) 构造 LL(1) 分析表

|              | a              | b             | c            | $ |
| ------------ | -------------- | ------------- | ------------ | - |
| **S**  | `S → Q c`   | `S → Q c`  | `S → Q c` |   |
| **Q**  | `Q → Q'`    | `Q → b Q'` | `Q → Q'`  |   |
| **Q'** | `Q' → a Q'` |               | `Q' → ε` |   |

**说明**：

- `S → Q c`：`FIRST(Qc) = {a,b,c}`，填入 a、b、c 列。
- `Q → b Q'`：`FIRST(bQ') = {b}`，填 b 列。
- `Q → Q'`：`FIRST(Q') = {a, ε}`；非 ε 部分 `{a}` 填 a 列；Q' 可空，故在 `FOLLOW(Q) = {c}` 填 c 列。
- `Q' → a Q'`：`FIRST(aQ') = {a}`，填 a 列。
- `Q' → ε`：在 `FOLLOW(Q') = {c}` 填 c 列。

**无多重定义冲突**，故该文法是 **LL(1) 文法**。□

### 3. 中缀表达式转前缀

给定文法（中缀表达式）：

```
E → E + T | T
T → T * F | F
F → id | ( E )
```

题目示例：`{ F.code = id.value }`

#### (1) 将 `a * -(b + c)` 转前缀

> 注：给定文法**不含一元负号 `-`**。这里 `-(b+c)` 中的 `-` 视为**一元负号（neg）**。若严格按给定文法，需扩展 `F → - F`。下面给出含一元负号的转换。

逐步转换：

1. `b + c` 的前缀：`+ b c`
2. `-(b + c)` 的前缀（一元 neg）：`neg(+ b c)`，记作 `- (+ b c)`
3. `a * -(b + c)` 的前缀：`* a - (+ b c)`

**前缀表达式**：`* a - + b c`（其中 `-` 为一元负号 neg）。

#### (2) 插入语义动作，实现中缀转前缀（结果存于综合属性 `code`）

语法制导翻译模式（前缀：操作符在前）：

```
产生式              语义动作
E → E + T           { E.code := '+' || E1.code || T.code }
E → T               { E.code := T.code }
T → T * F           { T.code := '*' || T1.code || F.code }
T → F               { T.code := F.code }
F → id              { F.code := id.value }          // 题目给定
F → ( E )           { F.code := E.code }
```

> `||` 表示字符串（token 串）拼接。前缀表达式中，操作符写在操作数之前：
>
> - `E → E1 + T` 的前缀为 `+ E1 T`，故 `E.code = '+' || E1.code || T.code`；
> - `T → T1 * F` 的前缀为 `* T1 F`，故 `T.code = '*' || T1.code || F.code`。

**若需支持一元负号**，扩展：

```
F → - F             { F.code := 'neg' || F.code }    // 或 '-' || F.code
```

**对 `a * -(b + c)` 的求值过程示意**（设 `a, b, c` 均为 id）：

- `F(a).code = "a"`
- `E(b).code = "b"`，`E(c).code = "c"`，`E(b+c).code = "+ b c"`
- `F((b+c)).code = "+ b c"`
- `F(-(b+c)).code = "neg + b c"` = `- + b c`
- `T(-(b+c)).code = "- + b c"`
- `T(a).code = "a"`，`T1 = a`，`F = -(b+c)`
- `T(a * -(b+c)).code = "* a - + b c"`
- 最终 `E.code = "* a - + b c"` ✓□

## 五、综合应用题

### 1. LR(1) 分析

文法：

```
S → A D c
A → a b | A d
D → D c | d
```

#### (1) 扩充文法

引入新开始符号 `S'`：

```
(0) S' → S
(1) S  → A D c
(2) A  → a b
(3) A  → A d
(4) D  → D c
(5) D  → d
```

#### (2) 求 FIRST / FOLLOW（用于构造 LR(1) 向前看符号）

**FIRST**：

- `FIRST(A) = {a}`
- `FIRST(D) = {d}`
- `FIRST(S) = FIRST(ADc) = FIRST(A) = {a}`

**FOLLOW**：

- `FOLLOW(S') = {$}`，`FOLLOW(S) = {$}`
- `S → A D c`：`FOLLOW(A) ⊇ FIRST(D) = {d}`；`FOLLOW(D) ⊇ FIRST(c) = {c}`
- `A → A d`：`FOLLOW(A) ⊇ {d}`（A 后跟 d）
- `D → D c`：`FOLLOW(D) ⊇ {c}`（D 后跟 c）
- 故 `FOLLOW(A) = {d}`，`FOLLOW(D) = {c}`

#### (3) 构造 LR(1) 项目集规范族

**I₀** = closure({[S' → ·S, $]})

```
[S' → ·S,   $]
[S  → ·A D c, $]
[A  → ·a b,  d]        ; A 的向前看 = FIRST(Dc$) = FIRST(D) = {d}
```

**goto(I₀, S) = I₁**

```
[S' → S·, $]
```

**goto(I₀, A) = I₂** = closure({[S → A· D c, $]})

```
[S → A· D c, $]
[D → ·D c,  c]         ; D 的向前看 = FIRST(c$) = {c}
[D → ·d,    c]
```

**goto(I₀, a) = I₃**

```
[A → a· b, d]
```

**goto(I₂, D) = I₄**

```
[S → A D· c, $]
[D → D· c,   c]
```

**goto(I₂, d) = I₅**

```
[D → d·, c]
```

**goto(I₃, b) = I₆**

```
[A → a b·, d]
```

**goto(I₄, c) = I₇**

```
[S → A D c·, $]
[D → D c·,   c]
```

项目集规范族共 **8 个状态** `I₀ ~ I₇`。

#### (4) LR(1) 分析表（ACTION / GOTO）

产生式编号见 (1)。`sj`=移入到状态 j，`rj`=用产生式 j 规约，`acc`=接受，数字=GOTO。

| 状态 | a  | b  | c  | d  | $   | S | A | D |
| ---- | -- | -- | -- | -- | --- | - | - | - |
| 0    | s3 |    |    |    |     | 1 | 2 |   |
| 1    |    |    |    |    | acc |   |   |   |
| 2    |    |    |    | s5 |     |   |   | 4 |
| 3    |    | s6 |    |    |     |   |   |   |
| 4    |    |    | s7 |    |     |   |   |   |
| 5    |    |    | r5 |    |     |   |   |   |
| 6    |    |    |    | r2 |     |   |   |   |
| 7    |    |    | r4 |    | r1  |   |   |   |

**填表说明**：

- I₁：`[S'→S·, $]` ⟹ `$` 列 `acc`。
- I₅：`[D→d·, c]` ⟹ `c` 列 `r5`（D→d）。
- I₆：`[A→ab·, d]` ⟹ `d` 列 `r2`（A→ab）。
- I₇：`[S→ADc·, $]` ⟹ `$` 列 `r1`；`[D→Dc·, c]` ⟹ `c` 列 `r4`。两者向前看符号不同，**无冲突**。
- 其余移入/转移按 goto 函数填写。

**无任何冲突，该文法是 LR(1) 文法**（同时也可验证为 LALR(1)）。

#### (5) 对输入 `a b d $` 进行 LR(1) 分析

| 步骤 | 栈（状态） | 栈（符号） | 输入        | 动作                                |
| ---- | ---------- | ---------- | ----------- | ----------------------------------- |
| 1    | 0          |            | `a b d $` | 移入 a，goto 3                      |
| 2    | 0 3        | a          | `b d $`   | 移入 b，goto 6                      |
| 3    | 0 3 6      | a b        | `d $`     | 规约`A → ab`（r2），goto(0, A)=2 |
| 4    | 0 2        | A          | `d $`     | 移入 d，goto 5                      |
| 5    | 0 2 5      | A d        | `$`       | **出错！**                    |

**出错分析**：此时栈顶为状态 5，对应项目 `[D → d·, c]`，其规约的向前看符号为 `c`；但当前输入是 `$`，`$ ∉ {c}`，且状态 5 无任何移入/转移动作 ⟹ **分析出错终止**。

> 题目说"栈里出现状态 2 终止"：按本构造，规约 `A → ab` 后栈顶为**状态 2**（步骤 4），随后移入 d 到状态 5，在读到 `$` 时无法规约而出错。各教材状态编号顺序不同，"状态 2"在题目编号体系中应对应此处出错相关状态。

**根本原因**：`a b d` **不是该文法的合法句子**。合法句子需以 `c` 结尾，例如 `a b d c`（`A→ab, D→d, S→ADc`）。输入 `abd$` 缺少末尾的 `c`，故分析必然在尝试规约 `D → d` 时因向前看符号不匹配而失败。□

### 2. SLR(1) 分析表与 LR(0) DFA（命题逻辑文法）

#### 6.1 写产生式

```
(0) S' → S
(1) S  → S ∨ S
(2) S  → S ∧ S
(3) S  → ¬ S
(4) S  → ( S )
(5) S  → a
```

#### 6.2 写这个语言的描述

该文法产生的语言是**命题逻辑（布尔）表达式**的集合，其中：

- `a` 是**原子命题**（命题变元/常量）；
- `∨` 是**析取**（逻辑或）；
- `∧` 是**合取**（逻辑与）；
- `¬` 是**否定**（逻辑非，一元前缀）；
- `( )` 用于改变运算优先级与结合性。

即：**由原子命题 a、二元运算 ∨/∧、一元运算 ¬ 以及括号构成的命题逻辑公式全体**。

> 注意：该文法是**二义文法**（`S → S ∨ S`、`S → S ∧ S` 未规定结合性与优先级），其 LR(0)/SLR(1) 分析表会出现**移入-规约冲突**，需借助运算符优先级与结合性声明（如 yacc 的 `%left`、`%right`）来消解。

#### 构造 LR(0) 项目集规范族（DFA，共 12 个状态）

题目给出 6 个状态，需推出另外 6 个。下面给出**全部 12 个状态** `I₀ ~ I₁₁`。

**I₀** = closure({S' → ·S})

```
S' → ·S
S  → ·S ∨ S
S  → ·S ∧ S
S  → ·¬ S
S  → ·( S )
S  → ·a
```

**I₁** = goto(I₀, S)

```
S' → S ·
S  → S · ∨ S
S  → S · ∧ S
```

**I₂** = goto(I₀, ¬)

```
S → ¬ · S
S → ·S ∨ S
S → ·S ∧ S
S → ·¬ S
S → ·( S )
S → ·a
```

**I₃** = goto(I₀, ()

```
S → ( · S )
S → ·S ∨ S
S → ·S ∧ S
S → ·¬ S
S → ·( S )
S → ·a
```

**I₄** = goto(I₀, a)

```
S → a ·
```

**I₅** = goto(I₁, ∨)

```
S → S ∨ · S
S → ·S ∨ S
S → ·S ∧ S
S → ·¬ S
S → ·( S )
S → ·a
```

**I₆** = goto(I₁, ∧)

```
S → S ∧ · S
S → ·S ∨ S
S → ·S ∧ S
S → ·¬ S
S → ·( S )
S → ·a
```

**I₇** = goto(I₂, S)

```
S → ¬ S ·
S → S · ∨ S
S → S · ∧ S
```

**I₈** = goto(I₃, S)

```
S → ( S · )
S → S · ∨ S
S → S · ∧ S
```

**I₉** = goto(I₅, S)

```
S → S ∨ S ·
S → S · ∨ S
S → S · ∧ S
```

**I₁₀** = goto(I₆, S)

```
S → S ∧ S ·
S → S · ∨ S
S → S · ∧ S
```

**I₁₁** = goto(I₈, ))

```
S → ( S ) ·
```

**goto 汇总**（DFA 的边）：

| from | 经 | to     | from  | 经 | to    |
| ---- | -- | ------ | ----- | -- | ----- |
| I₀  | S  | I₁    | I₅   | S  | I₉   |
| I₀  | ¬ | I₂    | I₅   | ¬ | I₂   |
| I₀  | (  | I₃    | I₅   | (  | I₃   |
| I₀  | a  | I₄    | I₅   | a  | I₄   |
| I₁  | ∨ | I₅    | I₆   | S  | I₁₀ |
| I₁  | ∧ | I₆    | I₆   | ¬ | I₂   |
| I₂  | S  | I₇    | I₆   | (  | I₃   |
| I₂  | ¬ | I₂    | I₆   | a  | I₄   |
| I₂  | (  | I₃    | I₇   | ∨ | I₅   |
| I₂  | a  | I₄    | I₇   | ∧ | I₆   |
| I₃  | S  | I₈    | I₈   | )  | I₁₁ |
| I₃  | ¬ | I₂    | I₈   | ∨ | I₅   |
| I₃  | (  | I₃    | I₈   | ∧ | I₆   |
| I₃  | a  | I₄    | I₉   | ∨ | I₅   |
| I₄  | — | (规约) | I₉   | ∧ | I₆   |
|      |    |        | I₁₀ | ∨ | I₅   |
|      |    |        | I₁₀ | ∧ | I₆   |

**规约状态**：I₄（r5: S→a）、I₁（r0 接受 S'→S）、I₇（r3: S→¬S）、I₁₁（r4: S→(S)）、I₉（r1: S→S∨S）、I₁₀（r2: S→S∧S）。

**冲突说明**：状态 I₁、I₇、I₈、I₉、I₁₀ 中既含可规约项目（`S→…·`）又含可移入项目（`S→S·∨S` / `S→S·∧S`），在 SLR(1) 下用 `FOLLOW(S) = {$, ∨, ∧, )}` 判断时仍会**冲突**（因 `∨`、`∧` ∈ FOLLOW(S) 同时又是移入符号）。这正是二义文法的体现，需用**优先级和结合性**消解：

- 通常规定 `¬` > `∧` > `∨`，`∧`、`∨` 左结合；
- 遇 `S→S∨S·` 与移入 `∨`：左结合 ⟹ 规约；
- 遇 `S→S∨S·` 与移入 `∧`：`∧` 优先级高 ⟹ 移入；
- 以此类推。□

| 题型 | 主要考点                                                                                                        |
| ---- | --------------------------------------------------------------------------------------------------------------- |
| 判断 | L 属性定义、Chomsky 文法层次、句柄定义、中间表示、句子推导、二义性语言、yacc/LALR、LR 类文法能力关系、Follow 集 |
| 填空 | 消除左递归（含 ε 右部的陷阱）、移入-规约冲突与优先级、S 属性求值方向、数组寻址三地址码、活跃变量分析           |
| 简答 | 文法二义性判定与语法树、基本块划分与流图、DAG 优化（常量折叠/死代码删除/复写传播）                              |
| 应用 | 正则式→ε-NFA→DFA→最小化、消除左递归+LL(1) 分析表、中缀转前缀的语法制导翻译                                  |
| 综合 | LR(1) 项目集/分析表/输入分析及出错诊断、二义文法 LR(0) DFA（12 状态）与 SLR(1) 冲突消解                         |

> **复习要点**：
>
> 1. 消除左递归当非递归右部含 `ε` 时，务必写成 `A → β A' | A'`（或 `βA' | εA'`），**不能**写成 `A → βA' | ε`，否则丢失语言。
> 2. LR(1) 与 SLR(1) 的区别在于**向前看符号**的精化（LR(1) 用项目自身传播的 lookahead，SLR(1) 用 FOLLOW 集）。
> 3. 二义文法的 LR 分析表必有冲突，需靠**优先级/结合性**消解，不能仅靠 SLR(1)。
> 4. 数组寻址 `A[i][j]`（行优先）：`base + (i × 列数 + j) × 元素大小`。
