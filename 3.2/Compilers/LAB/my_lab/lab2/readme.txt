【实验心得与收获体会】
在架构设计方面，三层架构的实践让我真切体会到"分层解耦"的价值。开发过程
中，我能够独立修改某一层的实现而不影响其他层——例如调整 Storage 的存储结
构时，Service 层的代码完全不受影响。这种"各司其职、互不干扰"的设计，不仅
让代码结构更加清晰，也使得单元测试变得更加容易，每一层都可以独立进行测试
验证。

设计模式的运用是本次实验的另一大收获。单例模式在 Storage 类中的应用，确保
了整个系统共享同一数据源，避免了数据不一致的问题；命令模式将每个操作封装
为独立的 Command 对象，使得添加新功能变得异常简单——只需新建一个类即可，
这让我真正理解了"开闭原则"的实践意义；工厂模式在 CommandFactory 中的使用，
让命令对象的创建逻辑集中管理，降低了代码的耦合度。这些模式不再是书本上的
抽象概念，而是解决实际问题的有效工具。

异常处理机制的设计过程让我认识到，良好的错误处理是系统健壮性的基石。通过
设计层次化的异常体系（AgendaException 作为基类，各具体异常继承扩展），我
学会了如何让错误信息既准确又友好。业务层抛出异常、表示层捕获并展示的模式，
使正常业务逻辑与错误处理代码清晰分离，大大提升了代码的可读性和可维护性。

总的来说，这次实验不仅让我掌握了三层架构和设计模式的实际应用，还让我体会到
良好架构设计和错误处理对软件质量的重要影响。这些经验将成为我未来软件开发道
路上的宝贵财富。
