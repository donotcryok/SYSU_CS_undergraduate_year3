【使用说明】
================================================================================

注意：所有脚本已整合到 scripts/ 目录下，请从项目根目录运行。

1. 编译项目
   > scripts\build.bat

2. 运行主程序
   > scripts\run.bat
   输入中缀表达式（如：1+2-3），程序输出后缀表达式（如：12+3-）

3. 运行单元测试
   首先需要下载 JUnit 库到 lib 目录（参考 lib/README.md）
   > scripts\test.bat

4. 运行性能测试
   > scripts\perf_test.bat
   输出 CSV 格式的性能数据到 data/perf_results.csv

5. 生成性能图表（需要 Python 环境）
   > python scripts\plot_perf.py
   图表保存到 img/performance_chart.png

6. 生成 Javadoc 文档
   > scripts\doc.bat
   文档生成到 doc/ 目录

7. 运行测试用例
   > scripts\testcase.bat
   或单独运行某个测试用例：
   > scripts\testcase-001.bat

【总结与展望】
=============================================================================1.理论与实践的结合：Dragon Book的示例代码简洁易懂，但实际工程应用需要考虑更多因素，如多线程安全、错误恢复等。这让我认识到理论学习与工程实践之间的差距。
2.尾递归消除的意义：虽然尾递归在函数式编程语言中可以被自动优化，但在Java等语言中需要手动重构。这让我理解了为什么某些语言（如Scheme）强调尾递归优化。
3.错误处理的艺术：一个好的编译器不仅要能检测错误，还要能从错误中恢复，尽可能多地报告错误。Panic-Mode是一种简单但有效的恢复策略。
4.单元测试的价值：完善的单元测试不仅验证了功能的正确性，还帮助我在重构过程中及时发现引入的错误。第14页，共14页
