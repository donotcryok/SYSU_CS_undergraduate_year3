这是一个非常关键的加分项。在数据量较小（只有几条测试数据）的情况下，查询速度的差异（毫秒级）肉眼几乎看不出来，但我们可以通过 **SQL Server 的“执行计划” (Execution Plan)** 来直观地展示“全表扫描”与“索引查找”的区别。

这是数据库课程设计中证明你懂“性能优化”的最有力证据。

请按照以下步骤，一步步完成并在实验报告中截图。

---

### 准备工作：确保数据字段存在

首先，你的 `Orders` 表之前没有“运单日期”字段，我们需要加一个，否则无法完成“运单日期”的索引优化。

请在 SSMS 中执行以下 SQL 补全字段：

**SQL**

```
USE LogisticsDB;
GO
-- 1. 给运单表加一个时间字段
ALTER TABLE Orders ADD OrderTime DATETIME DEFAULT GETDATE();
GO
-- 2. 给现有数据填上时间
UPDATE Orders SET OrderTime = GETDATE();
GO
```

---

### 第一步：开启“执行计划”显示

这是进行对比的核心工具。

1. 打开  **SSMS** 。
2. 在工具栏上找到一个图标，叫  **“显示估计的执行计划” (Display Estimated Execution Plan)** ，快捷键是 `Ctrl + L`。
3. 或者找到  **“包含实际的执行计划” (Include Actual Execution Plan)** ，快捷键 `Ctrl + M`（推荐用这个，运行查询后会多出一个标签页）。

---

### 第二步：场景一 —— 优化“车牌号”查询

 **目标** ：对比按车牌号查询车辆的效率。

#### 1. 建立索引前 (Before)

在查询窗口输入以下 SQL（**不要**选中 `CREATE INDEX` 语句）：

**SQL**

```
-- 模拟查询：查找车牌为 '京A88888' 的车辆
SELECT * FROM Vehicle WHERE PlateNumber = '京A88888';
```

1. 按下 **F5** 执行。
2. 点击结果窗口旁边的 **“执行计划” (Execution Plan)** 标签页。
3. **截图点** ：你会看到一个 **`Table Scan` (表扫描)** 或者  **`Clustered Index Scan`** 。

* *解释* ：这意味着数据库为了找到这辆车，把整张表从头到尾翻了一遍。效率低。

#### 2. 建立索引 (Action)

执行以下 SQL 创建索引：

**SQL**

```
CREATE INDEX IX_Vehicle_PlateNumber ON Vehicle(PlateNumber);
```

#### 3. 建立索引后 (After)

再次运行完全相同的查询语句：

**SQL**

```
SELECT * FROM Vehicle WHERE PlateNumber = '京A88888';
```

1. 查看  **“执行计划”** 。
2. **截图点** ：你会看到它变成了  **`Index Seek` (索引查找)** 。

* *解释* ：这意味着数据库直接通过索引树定位到了这行数据，没有扫描全表。效率极高。

---

### 第三步：场景二 —— 优化“运单日期”查询

 **目标** ：对比按日期范围查询运单的效率。

#### 1. 建立索引前 (Before)

**SQL**

```
-- 查询最近 7 天的运单
SELECT * FROM Orders WHERE OrderTime > DATEADD(day, -7, GETDATE());
```

* 执行并查看计划。
* **现象** ：应该是 **`Clustered Index Scan`** (因为 OrderID 是主键聚集索引，但我们查的是 Time，所以它还是得扫全表)。

#### 2. 建立索引 (Action)

**SQL**

```
CREATE INDEX IX_Orders_Time ON Orders(OrderTime);
```

#### 3. 建立索引后 (After)

再次执行查询。

* **现象** ：变成了 **`Index Seek`** (或者 `Index Range Scan`)。
* *注意：如果你的数据量特别少（比如只有5行），SQL Server 可能会认为“直接扫全表比读索引还快”，从而依然显示 Scan。为了强制看到效果，你可以多插入几十条数据，或者在报告中解释“数据量大时会变为 Seek”。*

---

### 第四步：场景三 —— 优化“司机工号”查询 (关联表查询)

目标：查询某个司机名下的所有异常记录。

注意：Driver 表的 DriverID 是主键，自动有索引。我们要优化的是 Abnormality 表中的外键 DriverID。

#### 1. 建立索引前 (Before)

**SQL**

```
-- 查询 ID 为 1 的司机的所有异常
SELECT * FROM Abnormality WHERE DriverID = 1;
```

* 执行并截图。
* **现象** ：**`Table Scan`** (全表扫描)。

#### 2. 建立索引 (Action)

**SQL**

```
CREATE INDEX IX_Abnormality_DriverID ON Abnormality(DriverID);
```

#### 3. 建立索引后 (After)

再次执行查询。

* 执行并截图。
* **现象** ： **`Index Seek`** 。

---

### 第五步：如何为了效果“造假数据” (可选)

如果你的表中只有 2 条数据，SQL Server 极其聪明，它会觉得“查索引还要翻书目录，只有两页纸我直接看正文算了”，所以它可能 **死活不走索引** 。

如果遇到这种情况，运行下面这个“暴力脚本”插入 1000 条假数据，立马就能看到效果：

**SQL**

```
-- 暴力插入 1000 条运单数据用于测试索引
DECLARE @i INT = 0;
WHILE @i < 1000
BEGIN
    INSERT INTO Orders (Weight, Volume, Destination, Status, VehicleID, OrderTime)
    VALUES (RAND()*1000, RAND()*10, '测试地址' + CAST(@i AS NVARCHAR), '已完成', 1, GETDATE());
    SET @i = @i + 1;
END
```

*运行完这个再测“场景二”，对比效果会非常明显（查询开销 Cost 会大幅下降）。*
